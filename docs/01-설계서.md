# 01 · 설계서

[지도](https://github.com/happytuco-arch/homepage-avatar/issues/1)의 결정을 구현 단위로 옮긴 문서입니다.
결정의 근거는 각 티켓에 있고, 여기서는 "무엇을 어떻게 만드나"만 적습니다. 용어는 `GLOSSARY.md`를 따릅니다.

## 화면 구조

```
BaseWindow (1280×800)
├─ siteView     WebContentsView  실제 사이트 (창 전체)
│                 └ 주입 DOM: 손 모양 커서, 강조 테두리 (사이트 코드는 수정하지 않음)
└─ overlayView  WebContentsView  투명, 창 아래쪽 띠(높이 300px)
                  ├ 왼쪽 아래: 일시정지 · 건너뛰기 · 질문 입력 · 마이크
                  ├ 가운데 아래: 자막 (글자 단위로 진행)
                  └ 오른쪽 아래: 3D 아바타 (assets/avatar.vrm 이 있으면 VRM, 없으면 코드로 그린 정장 인물)
```

- 사이트 조작은 메인 프로세스에서 `siteView.webContents.executeJavaScript`로 합니다. 메뉴는 `.nav__link`의
  글자(Works/Papers/Assignments)로 찾고, 항목은 `.card`(작품)와 `.post`(논문·과제)로 찾습니다.
- 사이트 뷰에는 preload를 붙이지 않습니다. 오버레이에는 `contextBridge`로 `window.avatar` 하나만 엽니다.

## 서비스 (메인 프로세스, 키는 `.env`에만)

| 모듈 | 하는 일 | 키가 없을 때 |
|---|---|---|
| `siteData` | Supabase REST 공개 읽기(projects·papers·assignments) | 동봉 스냅숏 `assets/site-snapshot.json` |
| `script` | Claude로 각색 대본 + 질문 목록 10개 생성, 자료 해시로 캐시 | 템플릿 대본(`templateScript`) |
| `answer` | 직접 질문 → Claude, 사이트 자료만 근거, 2~3문장 | 질문 목록에서 가장 가까운 답 |
| `tts` | ElevenLabs with-timestamps, `userData/audio-cache/<해시>.mp3+json` | 렌더러 `speechSynthesis`(인물별 pitch·rate) |
| `stt` | ElevenLabs Speech-to-Text | 마이크 버튼 숨김 |

## 대본 형식

```json
{ "scenes": [
  { "id": "intro", "page": null, "lines": [
    { "who": "avatar", "text": "안녕하세요…", "act": "wave" } ] },
  { "id": "works", "page": "Works", "lines": [
    { "who": "interviewer", "text": "이 게임은 왜 만들었어요?" },
    { "who": "avatar", "text": "…", "focus": { "kind": "card", "index": 0 } } ] } ],
  "faq": [ { "q": "…", "a": "…" } ] }
```

- 장면 순서: 인사 → Works → Papers → Assignments → 마무리(90도 인사) → "다시 보기".
- 사실은 사이트 자료에서만 가져옵니다. LLM 프롬프트에 자료 JSON만 넣고, 자료에 없는 내용은 쓰지 말라고 지시합니다.

## 투어 상태

`idle → playing ⇄ paused`, `playing → answering → playing`(멈춘 장면의 다음 줄부터), `playing → done`.

- 건너뛰기: 지금 줄을 끊고 다음 장면으로 갑니다.
- 직접 질문: 지금 말하는 줄이 끝난 뒤 답합니다.

## 정해 둔 기본값 (지도의 남은 흐릿한 항목)

- **캐시 무효화:** 대본은 자료 해시가 바뀌면 새로 만듭니다. 음성은 `목소리ID + 글자`의 해시로 저장하므로 바뀐 대사만 새로 만듭니다.
- **사이트 변경 대응:** 선택자를 찾지 못하면 그 동작만 건너뛰고 말은 계속합니다.
- **테스트:** 순수 함수(모음→입 모양, 템플릿 대본, 캐시 키, 질문 목록 매칭)는 `node --test`로 확인합니다. 화면은 직접 실행해 확인합니다.

## 배포

- electron-builder로 Windows(zip/portable)와 Mac(zip)을 만듭니다. Mac 빌드는 GitHub Actions의 macOS 러너에서 합니다.
- 서명하지 않습니다. 실행 시 뜨는 경고를 넘기는 방법은 `docs/사용가이드.md`에 적습니다.
